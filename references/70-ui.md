# 游戏 UI：324 个 NDF 的分层、五根挂载与四条解析链

> 适用：「改一个图标 / 改一句提示文字 / 改面板颜色」「AG 战役界面怎么改」「HUD 加一个元素」
> 「我加了单位为什么面板上没图标 / 特性不显示」。
> 本文件只讲**UI 数据的结构与链接**。改动落地工程（换行/锚点/编译/验收）走 `40-engineering.md`；
> 造单位本身走 `20-unit-authoring.md`；**给编辑器写 UI（WinForms/PySide 界面）不属于本文件**，走 `eugen-ndf-editor-pattern`。

---

## 0. 一句话结构

WARNO 的 UI 是 **BUCK** 框架：**模板（template）定义字段 → 实例填值 → 样式表按 token 查颜色/字体 → 纹理表按 token 查图 → 资源根把视图注册进层**。
UI 层 **只读 gameplay**（`$/` 反向引用实测 0 条），与 gameplay 之间是**字符串契约**，不是对象引用。

> ⚠ 这是本板块最重要的一条：**UI 与 gameplay 完全解耦**。所以改名/改错 token 不会报错，只会静默显示空图、默认色、原始 token 字样。

## 2. 文件构成：按职责分 6 类（不是按目录）

| 类 | 目录 | 文件数 | 干什么 | 改它的后果 |
|---|---|---|---|---|
| **① 模板** | `CommonData/UserInterface/Use/Common/Templates/` | 45 | 定义 `template BUCKXxxDescriptor` 的字段与默认值。**不含实例** | 改这里 = 改**类**，全游戏所有同类控件变 |
| **② 样式** | `CommonData/UserInterface/Style/`、`GameData/UserInterface/Style/` | 16 | `TUIStyleGuide`：8 张 MAP（颜色/字号/线宽/边距/字体） | 改 token 值 = 全局换肤；唯一**不碰布局**的安全区 |

| **④ 生成数据** | `GameData/Generated/UserInterface/`、`/Strategic/` | 7 | 由 `XxxFileWriter` 从 gameplay 扫出来的**只读桥表** | 直接改会被下次编译覆盖（见 §7） |

> `CommonData/` 改动的爆炸半径更大：`CommonStyleGuide` 同时被 WARNO 与同引擎其他游戏族共享。

## 3. 五个根 + 五个层：UI 的唯一挂载点

**每个场景有一个根资源对象**，它是引擎拉起该场景 UI 的入口。根上挂 `UILayer`（画在哪一层）与 `ViewDescriptors`（有哪些视图）。

| 场景 | 根对象（类型） | 文件 | UILayer | LayerList 对应 |
|---|---|---|---|---|
| 战斗内 HUD | `UIInGameResource` (`TUISpecificInGameResources`) | `Use/InGame/UIInGameResources.ndf` | `$/UserInterface/UILayer_2DInterface_InGame` | `CalqueArray_2DInterface_InGame` |
| 大厅 / 卡组编辑 | `OutGameResourceSpecific` (`TUISpecificOutGameResources`) | `Use/OutGame/UIOutGameResources.ndf` | `..._OutGame` + `..._OutGame_Warning` + `UILayer_DragAndDrop` | `CalqueArray_2DInterface_OutGame` |
| 将军模式（AG） | `StrategicResource` (`TUISpecificStrategicResources`) | `Use/Strategic/UIStrategicResources.ndf` | `UILayer_2DInterface_InGame`（复用）+ LD Hint 层 | 同 InGame |
| 陈列室 / 军械库 | `ShowRoomResource` (`TUISpecificShowRoomResources`) | `Use/ShowRoom/UIShowRoomResources.ndf` | — | `CalqueArray_2DInterface_ShowRoom` |
| 大厅 Hub（跨屏容器） | `OutGameHUBContainerResource` | `OutGameHUBContainerResources.ndf` | — | — |

**`ViewDescriptors = MAP [("键", ViewDescriptor(...))]` 是视图注册表**，注册数实测：InGame **33** / Strategic **23** / ShowRoom **5**。
引擎按 key 拉视图，`UILayer` 决定绘到哪条 `CalqueArray`。层级清单在 `CommonData/System/LayerList.ndf`（`InterfaceLayers`，29 项，顺序即 Z 序）。

> ★ `$/UserInterface/UILayer_*`、`$ /UserInterface/UIUniformDrawer` 这类对象在 **4564 个 NDF 源与 exe 明文串里都找不到定义**，只有引用（实测）。
> 它们是引擎侧/预编译侧的契约对象：**能引用，不能定义**。想加新层只能复用现有层 + `LocalRenderLayer` 调顺序。

## 4. BUCK 组件体系：模板 → 实例 → 父子

```ndf
// ① 模板（CommonData/UserInterface/Use/Common/Templates/BUCKButtonDescriptorTemplate.ndf）
template BUCKButtonDescriptor
[
    ElementName : string = "",
    HasBackground : bool = false,
    BackgroundBlockColorToken : string = "",   // ← 颜色走 token，不写颜色值
    Components : LIST<TBUCKContainerDescriptor> = [],   // ← 容器可嵌套
]

// ② 实例（任意 View 文件里）
UnitLabelUnitIcon is TBUCKSpecificLabelUnitIconDescriptor
(
    ElementName = "UnitIcon"
    ComponentFrame = TUIFramePropertyRTTI ( MagnifiableWidthHeight = [...] )
    HasBackground = true
    BorderLineColorToken = "Blanc"
)

// ③ 注册进视图 → 视图再注册进根 ViewDescriptors
```

三条铁律：
1. **`ElementName` 是运行时句柄**。代码/`ComponentByName` 按它找控件；改名 = 该控件在最上层找不到，静默消失。
2. **`is BUCKXxxDescriptor` 才是实例**。`BUCKXxx` 出现在 `is` 右边但左边是 `template` → 那是模板不是实例。
3. **布局靠 `ComponentFrame`（`TUIFramePropertyRTTI`）**：`AlignementToFather` / `MagnifiableWidthHeight` / `LocalRenderLayer`。不是 CSS，没有 flex。

## 5. 四条解析链（"链接关系"的实质）

UI 的跨文件链接**几乎不走 `$/` 对象引用，而是走"字符串 token → MAP 查表"**。四条链，任一环断掉都**不报错**。

### 5.1 纹理链

```
控件  TextureToken = "Texture_RTS_H_AA"     (或 BackgroundTexture / ButtonTexture / SpecialtyTextureName)
  ↓ 查 TBUCKToolAdditionalTextureBank.Textures  (MAP: 名字 → ComponentState → 纹理对象)
     GameData/UserInterface/Use/Common/BUCKTextureBank.ndf   (Base_AdditionalTextureBank)
     GameData/Generated/UserInterface/Textures/*.ndf         (各生成 bank)
  ↓
TUIResourceTexture_Common ( FileName = "GameData:/Assets/2D/Interface/UseInGame/Minimap/unit.png" )
  ↓ 编译
Gen/PC/Texture/Assets/2D/Interface/.../unit.tgv
```

**改图 = 改 `FileName` 指向的 PNG，或改 MAP 里"名字 → 对象"的映射。**
实测：`MenuIconTexture` 41 种取值、`ButtonTexture` 2898 种取值，**全部能在纹理 bank 里命中**（0 缺失）——所以「图标空白」不是缺定义，是拼写或 MAP 键不匹配。

### 5.2 颜色链 / 5.3 文字链

| 控件字段 | 查哪张 MAP | 在哪个对象 | 键数（实测） |
|---|---|---|---|
| `BackgroundBlockColorToken` | `BlockColorsMap` | `DefaultStyleGuide` / `CommonStyleGuide` | 329 |
| `BorderLineColorToken` / `LineColorToken` | `LineColorsMap` | 同上 | 96 |
| `TextColorToken` / `ColorToken` | `TextColorsMap` | 同上 | 526 |
| `TextStyleToken` / `TextStyle` | `TextStylesMap` | 同上 | 32 |
| `TypefaceToken` / `TextTypefaceToken` | `Typeface` | 同上 | 16 |
| `TextSizeToken` | `TextSizesMap` | `DefaultStyleGuide` | 138 |
| `BorderThicknessToken` | `LineSizesMap` | 同上 | 22 |
| 边距 `MagnifiableMargin` | `MagnifiableMarginsMap` | `DefaultStyleGuide` | 4 |

`TUIStyleGuide` 只有这 **8 个字段**，全部是 `MAP[("键", MAP[(~/ComponentState/X, 值)])]`。
⇒ **同一控件在不同状态（Normal/Hovered/Clicked/Grayed/Toggled…）可以给不同值**，这是「按钮按下去变色」的实现方式。

> ★ **两个 StyleGuide 并存**：`CommonStyleGuide`（CommonData，跨游戏）与 `DefaultStyleGuide`（GameData，WARNO）。
> 控件默认查哪个由**根资源**的 `MainStyleGuide = ~/DefaultStyleGuide` 决定（5 个根全部指向 Default）。
> 查不到 token → 回落 `"Default"` 或空值，**不报错**。这就是「改了颜色没变化」的第一嫌疑。

### 5.4 本地化链

```
控件  TextToken = "XXXX"  +  DicoToken = "dico_interface_ingame"
  ↓
Localisation/<Lang>/*.dic 或  Localisation/dico_interface_ingame.csv
```

实测 token 用量：`dico_interface_ingame` **441** 次、`dico_interface_outgame` **387** 次、`dico_units` 31、`dico_maps` 19、`dico_dialogues` 23。
⇒ 界面上 80% 的文字走 `dico_interface_*`；**单位名走 `dico_units`（`NameToken`）**，两者不能混用。

## 6. gameplay → UI 的接口：`TUnitUIModuleDescriptor`

单位在 UI 上长什么样，由单位 `ModulesDescriptors` 列表里的 **`TUnitUIModuleDescriptor`** 决定（2898 个单位全都有）。**共 10 个字段**：

| 字段 | 作用 | 取值域（实测） |
|---|---|---|
| `NameToken` | 显示名 | `dico_units` 的 key |
| `MenuIconTexture` | 建造栏/卡池图标 | 41 种，如 `Texture_RTS_H_AA` |
| `ButtonTexture` | 单位卡片大图 | 2898 种，一单位一张 |
| `InfoPanelConfigurationToken` | **信息面板布局档位** | 8 种：`Default` 846 / `Infantry` 1063 / `avion` 390 / `VehiculeTransporter` 270 / `HelicoDefault` 167 / `VehiculeSupplier` 82 / `HelicoTransporter` 55 / `HelicoSupplier` 25 |
| `UnitRole` | 兵种角色（影响排序/图标） | 19 种：`reco` 389 / `appui` 386 / `infantry` 308 / `AA` 281 / `transport` 269 / `AT` 248 / `armor` 180 / `hq_inf` 117 … |
| `SpecialtiesList` | 特性图标行 | 27 种，如 `_smoke_launcher` 408 / `_amphibie` 333 / `_leader` 319 |
| `PriceCategory` | 价格档（决定价格条颜色） | 如 `tank_A` |
| `DisplayRoadSpeedInKmph` | 面板显示的道路速度 | 整数 km/h |
| `UpgradeFromUnit` | 升级来源（面板显示"由 X 升级"） | 单位对象引用 |
| `TypeStrategicCount` | AG 计数归类 | `ETypeStrategicDetailedCount/*` |

**三条必记的联动规则：**

1. **`SpecialtiesList` 的每个值必须在 `UnitSpecialties.ndf` 里有对应 key**（该文件定义 **83** 个 key）。
   缺 key → 图标行少一个，**不报错**。
2. **`MenuIconTexture` / `ButtonTexture` 必须在某个 `TBUCKToolAdditionalTextureBank` 里注册过**。
   拼错 → 建造栏出现空白方块。
   → 但「给单位换成**自己画的**卡面」要动 PNG 美术资源，**不在本章**，走 `20-unit-authoring.md §2.5`
   （一张 256² PNG + 注册行 + 单位字段，三步）。本章只管 token 链本身。
3. **`InfoPanelConfigurationToken` 决定面板有几栏、显示哪些字段**。
   把它从 `Default` 改成 `Infantry`，面板会切到步兵布局（多出人员/武器分组），**这是"新单位面板显示怪"的常见根因**。

> `SpecialtiesList` 用下划线前缀（`_sf`、`_para`），而 `UnitRole` 不带（`sf` 是另一个 key）。
> 两者在 `UnitSpecialties` 里是**不同条目**，别互相当别名用。

## 7. 生成层：16 个文件 ← 15 个 FileWriter

| 文件 | FileWriter | 产出的对象 | 谁消费 |
|---|---|---|---|
| `BattleOrder.ndf` | `BattleOrderFileWriter` | 580 × `TBattleOrderSubordination`（指挥链节点：上级 + 名称 token + 背景纹理） | `StrategicBattleOrderResources` |
| `Strategic/BattleOrderResources.ndf` | `StrategicBattleOrderResourcesFileWriter` | `TStrategicBattleOrderResources`（卡片 → 上级节点的 MAP） | `UIStrategicResources.BattleOrderResources` |
| `UnitSpecialties.ndf` | `UnitSpecialtiesFileWriter` | `TUnitSpecialtiesContainer`（83 key → 图/提示/是否作筛选器） | `UISpecificUnitInfoPanelView` / `ShowRoomArmoryComponent` |
| `WeaponTraits.ndf` | `WeaponTraitsFileWriter` | `TWeaponTraitsContainer` | `UISpecificUnitInfoSingleWeaponPanelView` |
| `WeaponsMinMax.ndf` | `WeaponsMinMaxFileWriter` | `TWeaponsMinMaxValuesInterfaceHelper`（全武器数值 min/max，用于画条） | 武器面板（按固定对象名取） |
| `DivisionTypes.ndf` | `DivisionTypesFileWriter` | `TDivisionTypeDescriptions`（8 个师类型 → 图标名） | `UIOutGameResources.DivisionTypeDescriptions` |
| `UISpecificCountriesInfos.ndf` | `UICountriesInfosFileWriter` | `unnamed TUISpecificCountriesInfos` | 国旗/国名 |
| `Textures/DivisionTextures.ndf` 等 9 个 | 各类 `*TextureFileWriter` | 766 个 `TUIResourceTexture_Common` | 全部视图 |

**注入模式（关键）**：生成层对象从不被"直接引用"，而是由 **Use 层的 Resources 文件用 `~/` 挂字段**：

```ndf
// UIStrategicResources.ndf
BattleOrderResources = ~/StrategicBattleOrderResources
// UIOutGameResources.ndf
DivisionTypeDescriptions = ~/DivisionTypeDescriptions
// UISpecificUnitInfoPanelView.ndf
UnitSpecialtiesContainer = ~/UnitSpecialties
```

⇒ **「加了单位但面板不显示特性」的排查顺序**：`SpecialtiesList` 值 → `UnitSpecialties.ndf` 有没有这个 key（它是**编译期生成**的，不是你手写的） → 视图有没有 `UnitSpecialtiesContainer` 字段。
前两步任一处缺，UI 静默少一行。

## 9. 六条改动路径（想改什么 → 改哪）

| 想改 | 改哪 | 具体字段 |
|---|---|---|
| 换个图标（单位建造栏） | 单位自身的 `TUnitUIModuleDescriptor` | `MenuIconTexture`（改指向已有纹理名），或改该纹理对象的 `FileName` |
| 换单位**卡面**（兵牌，要自己出图） | 不在本章 → `20-unit-authoring.md §2.5` | 新建 256² PNG + 纹理 bank 注册 + `ButtonTexture` |
| 换个图标（面板/特性） | `Generated/UserInterface/Textures/*.ndf` | `TUIResourceTexture_Common.FileName = "GameData:/Assets/2D/..."` |
| 换界面整体配色 | `Style/DefaultStyle/DefaultStyleGuides.ndf` | `BlockColorsMap` / `TextColorsMap` 里对应 token 的 `TColorRTTI` |
| 改一句提示文字 | 本地化 csv/dic | 该 token 在 `dico_interface_ingame` 的译文 |
| 隐藏一个 HUD 元素 | 根资源的 `ViewDescriptors` | 删掉对应 MAP 条目（**不是**删视图文件） |
| HUD 加一个元素 | `Use/InGame/UIInGameResources.ndf` | 先写 ViewDescriptor，再加进 `ViewDescriptors` MAP |
| 改 AG 战役界面 | `Use/Strategic/UIStrategicResources.ndf` + `UISpecificStrategic*View.ndf` | `ViewDescriptors` 23 个键 |
| 改单位面板字段排布 | `InfoPanelConfigurationToken` 指向的配置 | 8 个档位，建议复用不要新建 |

**新增一个 HUD 控件的最小链路（4 步，缺一不可）**：
1. `Use/InGame/<你的>.ndf` 写实例（`is BUCKContainerDescriptor` 之类）→ 2. 挂进某视图的 `Components`
3. 视图的 ViewDescriptor 加进根 `ViewDescriptors` MAP → 4. 用到的纹理/token 在 bank / StyleGuide 里存在

## 10. 陷阱清单（全部实测）

1. **`Generated/` 的 UI 文件会被 FileWriter 重生成**。手改 `UnitSpecialties.ndf` 加一个特性 → 下次编译被覆盖。**特性 key 只能来自单位 `SpecialtiesList` 的实际使用**。
2. **token 拼错不报错**。颜色回落默认、纹理变空白、文字显示成原始 token 串。验收必须**看画面**，不能看编译通过。
3. **`ElementName` 重名 = 后者覆盖前者**，且无警告。复制控件后必改。
4. **`CommonData/` 与 `GameData/` 两套 StyleGuide**，改错一边等于没改。
5. **`UILayer_*` / `UIUniformDrawer` 无法定义，只能引用**（§3 实测）。
6. **`ViewDescriptors` 的 key 是引擎侧查找键**，改名 = 视图不加载。
7. **纹理 MAP 的键必须唯一**；同名键在多个 bank 里会按加载顺序覆盖。
8. **UI ndf 同样是 CRLF/编码坑**（见 `40-engineering.md`）：整文件重写换行 = 数十万行假 diff。UI 文件普遍 400~3500 行，误伤比 gameplay 小但一样难查。
9. **`InfoPanelConfigurationToken` 写错 → 面板空**（8 个合法值之外无回落）。

## 11. 验收（按顺序，跳步会误判）

1. **编译过**（守卫脚本，不看退出码）
2. **界面能起来**（进对应场景不崩）
3. **元素在**（该出现的控件出现了）
4. **样子对**（图不空、色不是默认灰、字不是 token 串）
5. **交互对**（点得动、hover 有反馈、列表能滚）
6. **换语言/换分辨率不塌**（`Magnifiable*` 字段是否被硬编码像素破坏）

## 12. 待验清单（【推断】，未实测）

- 【推断】mod 覆盖 UI 的方式：把 `GameData/UserInterface/...ndf` 按同名路径放进 mod 工程 → 编译进 `Gen/NDF/UI/*.ndfbin`。
  实测到 mod 产物里确有 `Gen/NDF/UI/{BattleOrder,Components}.ndfbin`（17 KB / 368 KB），但**未做"改一个 token → 进游戏看变化"的闭环验证**。
- 【推断】`Components.ndfbin`（368 KB）是 `GameData/UserInterface/Use/**` 的合并编译单元（单文件粒度未验证）。
- 【推断】`MinMaxValuesInterfaceHelper` 仅被 C++ 侧按固定对象名取用（NDF 里只有自身文件出现 2 次，无 `$/` 引用方）。
- 【推断】`$/UI/` 命名空间映射到 `GameData/Generated/UserInterface/`（由 `$/UI/BattleOrder/*` 指向该目录对象反推，未见显式声明）。
